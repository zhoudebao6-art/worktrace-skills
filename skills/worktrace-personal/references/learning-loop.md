# 分控个人学习循环 v1

状态：idle → claim_batch → inspect → reconstruct → verify → persist → done。
缺资料：verify → persist(blocked/unknown) → waiting_for_new_evidence。
故障：当前批次保留 open → 本次退出 → 下次恢复。

1. 先按任务、案件或可观察的一段工作区分片段；无法确定同一任务时分别保留，不拼成完整故事。
2. 核对输入→操作→判断→验证→产出。窗口切换不能证明点击了哪个按钮；采样之间的动作标未知。操作步骤写明软件、对象和可见字段，不能只有“处理了客户”。
3. 逐对比较 AI 与人工版本：保留改了什么、如何影响结果。真实修改理由才写 observed；自己推测的心理原因只能 inferred。情绪只从明确话语描述，不推断稳定人格或健康状态。
4. 反向检查：照这些步骤能否知道起点、每步所需输入和结束条件？不能时列缺项。是否把草稿/打开页面误当完成？是否漏了等待外部回复、权限不足、异常分支？
5. 存入 learning.summary。证据范围由领取批次固定；日总结是多批片段的查询汇总，不能把跨日/跨任务的 50 个事件宣称成完整一天。

v0.5.2 选样先读最早 1000 条未归组记录的有限字段，在窗口内优先正文、截图、document.version 和 task/artifact 证据，再处理活动元数据。相同小时、应用、状态及完整窗口标题才可归为一个代表片段；标题不同、正文或图像不同不能合并。选满代表数量后，仍会计入同窗口内已选组的重复片段；没有被选中的事件不标为已处理。检查 selection.scanned、unselected_in_window、has_more_beyond_window；它们是领取时快照，不是全库实时待处理总数，旧批次可能没有 selection。正文优先不保证窗口外最新内容已经检查。

保存返回不确定时先读取 personal_history 和当前批次，确认是否已存在同一 batch_id 的总结，再重试相同内容；不能因为日报生成错误重跑模型或写第二份结论。日报可用部署目录的管理入口重建：

```powershell
& '<运行目录>\runtime\node.exe' '<运行目录>\src\admin-cli.mjs' --command personal-digest --role collector --dir '<运行目录>\data'
```

## 原件核验与专业岗位

document.version 的 text 是有限解析结果，file_sha256/previous_event_id 指向已存版本与前一版本。化学结构、配比、上下标、数学公式、数值范围、单位、表格公式缓存、修订与批注都应核对具体原件；PDF 当前保留原件而不解析正文。不能因为文件原件存在就写 observed“已理解结构式”。自动执行器没有原件读取工具，只能报告未核实项。

交互复盘需要原件时，先确认该 document.version 在本批范围内，将 `{"event_id":"<事件UUID>"}` 保存为本机请求 JSON，再导出到**此前不存在**的审阅文件：

```powershell
& '<运行目录>\runtime\node.exe' '<运行目录>\src\admin-cli.mjs' --command file-extract --role collector --dir '<运行目录>\data' --input '<本机请求.json>' --output '<新的审阅文件.docx>'
```

扩展名按事件中真实类型设置。只审阅已存版本，不覆盖工作原件、不擅自运行附件宏、不以读取权限代替业务修改权限。引用原事件 ID 与实际核验范围；看不清、工具不支持或未实际读取的部分保留 unknown。若脱机没有模型访问，继续保存原始证据并标注个人分析待完成，不伪造总结或更换身份。

轻量建议：每天一次下班总结；高流量岗位可由总控调整到午间+下班。未处理完留在队列，下一次继续。默认每次三批/六张图；总控先看摘要和缺口再决定增加预算，避免全屏持续多模态推理。

质量门槛（语义检查由 Codex 与真实案例完成，结构校验只挡格式/引用错误）：
- 每项观察能定位原始证据；与记录不符的结论撤回。
- 每个判断有依据，或清楚标出尚不清楚。
- 输出有成功/失败/未验证之分。
- 初次样本只记录个人做法，不扩大为通用规则。
- 真正可替代岗位需要总控在未用于提炼的案例回放，记录遗漏、错误和需要人工介入的原因。
