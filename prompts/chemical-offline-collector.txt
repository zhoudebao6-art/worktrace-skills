请在这台化工专利案件员工的 Windows 电脑上，基于我们已有的 WorkTrace 技能，完成“独立离线分控”的实现、部署与验收，然后按工作时段持续记录和总结。不要只给方案。

一、角色与边界
这台电脑固定对应一位化工案件员工，只是分控。公司总控尚未上线，而且未来总控在另一局域网。当前不依赖总控登记、心跳、下发任务或网络共享；采用本机保存，数日后人工带回资料。不要把本机配置成总控，不扫描其他电脑，不伪造总控地址、证书或在线状态。
这里“离线”仅指不连接公司总控。Codex 模型调用仍需该电脑自己的登录与网络。员工账号使用 gpt-6.1-sol、reasoning_effort=high；不可用时记录阻塞，不静默更换模型。断网或额度不足时，本地采集与持久化应继续，模型任务等待恢复。
公司已经统一告知员工此次工作记录与方法学习。保持可见托盘和暂停入口，不反复索要逐条授权、不抢鼠标键盘、不自动操作微信、发送消息、提交专利或改变工作原件。

二、源码、目录与首次配置
在当前目标电脑自行取得源码。公开发布页：https://github.com/zhoudebao6-art/worktrace-skills/releases/tag/v0.3.0 。下载 Assets 中的 worktrace-skills-v0.3.0.zip 和 SHA256SUMS.txt；无需 GitHub 账号或私有维护仓库权限。先从同一个 v0.3.0 发布取得 SHA256SUMS.txt，计算 ZIP 的 SHA256 并核对唯一对应项；不沿用旧版校验值。本维护仓库现已公开，无需访问其他私有仓库，不索取他人凭据，不尝试读取发起方电脑的 E: 盘、本地文件链接或局域网。访问失败时报告具体网络错误，不编造源码。v0.3.0 增加外部导入、分层检索和离线候选验收，但没有自动补齐下文无总控首次部署能力。核验原包后完整解压，阅读 AGENTS.md、docs/download.md、docs/deployment.md、docs/nightly-loop.md，以及 worktrace-collector、worktrace-personal、worktrace-evidence 的 SKILL.md 与 references。
读取现有源码，不假定功能存在。已知 v0.3.0 的 collector 首次初始化必须有 enrollment；自动学习只消费总控任务；现有 wpack 导入要求相同 org_id 且设备已登记，并不会自动登记包内 devices。以下离线功能属于需要补齐并实测的部分，不能照搬联网 Join 后把失败当成功。
原下载包与官方源码保留不改。在独立派生源码目录实施兼容扩展，生成注明基础版本、修改清单、模式版本和 SHA256 的新清单；不要修改原包后伪装为仍通过官方清单。将维护源与总控技能内的引擎镜像同步更新；本地部署明确记录派生来源，遇到安装器来源校验阻止时提供正式派生安装入口，不绕过校验或覆盖既有技能。
建议目录：D:\WorkTraceChemSource（派生源码）、D:\WorkTraceChem（运行程序与 data）、D:\WorkTraceChemBackups（版本化备份）、D:\WorkTraceChemHandoff（交接成果）。不存在 D 盘时选实际非系统盘，先报告路径。不将数据库写到技能目录或临时目录。缓存和临时文件遵循本机 AGENTS.md；有 D 盘用 D:\codex+。
首次只集中确认必需的信息：员工唯一编号与显示名、公司名称或内部代号、允许记录的业务软件和资料目录、实际工作日及上下班时间。已有有效身份或部署先核对并沿用，不重复初始化。未获得资料目录时可以先完成软件部署与合成测试，但不能扫描整盘代替授权范围或声称已学习业务。

三、补齐独立离线运行和未来接纳身份
新增明确的 collector 离线初始化模式。保持 role=collector，持久化唯一的 org_id、employee_id、device_id、installation_id、stream_id；公司身份待未来总控接纳，不冒充已经登记成功。已有公司标识就沿用；没有时为本次公司试点建立一次稳定标识，并将以后总控接纳该标识的方法写入交接说明。
总控地址未配置是正常状态，应显示“离线记录，等待人工移交”，关闭远程同步重试，不生成假 HTTPS 地址或连接凭据。仍保留原有事件规范、原始事件 ID、顺序、策略哈希和附件哈希。现有联网模式不受影响。
同时提供离线接收与演练入口：未来尚未初始化的总控可明确接纳这个公司标识和原设备登记，再以自己真实的主机配置生成服务与证书，导入本次资料；不能在未来重新随机生成公司/设备编号后期待旧包自动导入。若接收端已绑定另一公司标识，拒绝无声合并并出具迁移说明，保留原始来源和原库，禁止重写历史事件编号或绕过身份校验。
不得将拷回的数据目录直接当新电脑上的活跃分控启动；它带有原主机绑定。移交和汇总不得覆盖未来总控已有数据库。

四、化工岗位的证据采集与方法学习
被动记录工作范围内的操作证据；保留工作时段、暂停、锁屏、不可访问和采样缺口。先用真实软件验证 UIA 正文覆盖，必要时对已允许的业务窗口按需取图。默认仅应用元数据不足以学习岗位，编辑框跳过、截图遮挡或复杂化学结构读不到时必须说明。
针对明确允许的工作资料目录，补充只读的保存版本取证：保留实际交底、文书、表格、检索材料及其后续修改版本、来源路径、时间、原文件哈希和解析版本。文件稳定保存后再读取；变化时重试，去重保存，不改原稿，不对全盘或私人目录采集。解析 Word/PDF/表格有缺口时保留原件与缺口，不凭截图臆造内容。新增文件证据使用有版本、可迁移的结构；不得伪装成员工手动反馈或现有不兼容的事件类型。
优先学习员工实际怎样：理解技术交底、发现资料缺项、核对组分/配比/单位和工艺条件、处理结构式与反应关系、联系实施例/对比例和测试证据、组织与修改权利要求及说明书、检索对照、回复客户或审查问题、交叉核验和交付。这里只是观察维度，不是预设员工必须使用的做法；没有发生的流程不补写。
化学式、结构式、名称、数值、范围、单位、条件和实验结论必须能回到原件；区分客户原始数据、员工修改、AI 推断和未知。OCR 或多模态识别不确定时保留原图定位，不把猜测作为事实；不得生成虚构实验数据、检索结果或业务完成状态。
每项方法记录触发条件、输入、软件及对象、实际动作 action、判断 decision、核验 check、输出、异常/等待分支、人工修改、结果和原始证据引用。判断理由未观察到就标 unknown，推测标 inferred。未知客户/案件编号保持未知，临时工作片段编号不能冒充正式案件编号。
按已确认的案件或片段分组，保留原稿—修改稿—可观察结果的关联。不把打开文件当作办结，不把草稿当已发送，不把窗口标题或同名联系人当唯一身份。

五、不依赖总控的本地学习循环
复用 worktrace-personal 的结构与已有学习执行器，新增本机日任务调度。仅启用 Configure-Learning 或运行 worker-run 不够，必须验证本地确实产生并消费 personal.summarize 任务。
学习窗口按员工实际下班时间设置，默认下班后开始、当日 23:59 结束；白天主要采集，避免干扰员工。每日本机模型调用先设最多 6 次，单任务最多 3 批、每批默认 50 条摘要，每次模型调用最多 3 张有必要的图；只处理新增证据。结合员工实际样本检查积压；达到预算保存检查点，不无限追加调用、不丢弃待处理记录。
任务使用员工/设备/日期的稳定幂等键；反复启动不重复花费。暂停、重启、超时、断网均保留状态；失败不每几秒反复调用。无新证据立即结束。手动复盘与自动学习互斥，不学习自己生成的总结来制造新的证据。
本地任务须标明 local 来源，与未来总控任务区分；本地任务回执不得按既有同步逻辑上传成总控未知 job，否则会阻断整批同步。
保存结构化 learning.summary 或显式版本化的兼容扩展，再生成便于人读的日总结：当天处理片段、已观察到的方法、实际修改、例外、结果、证据覆盖和缺口。文件证据必须进入领取、引用、保存和移交链路；不能只有外部文件夹、模型却从未读取。
形成个人方法候选和待验证清单，保留适用条件、反例、来源、置信与未知项。不要直接自动安装候选 Skill、改变业务规则或宣称几天观察已能替代该员工。总控上线后再做跨员工比较和留出案例评估。
问题平时累积，非阻塞问题最多在下班时汇总一次，不要求员工每做一步解释；没有回答就保持未知。
记录与学习需要真实的持久服务/当前用户登录启动机制；不把技能文字或聊天窗口当后台调度器。核实休眠、关机、注销的影响；不自行修改系统电源策略。

六、数日后的完整移交
现在就实现并验收“生成交接包”入口，之后我说“结束试点，准备带回数据库”时可直接运行。提供两类交付：
1. 可汇总包：原始事件、规范化文件证据与必要原件/版本、截图附件、采集策略、个人总结、引用链及来源身份清单。沿用兼容 wpack 时按现有 10000 事件/100 MiB JSON 限制校验；超限要明确分卷并保证引用和依赖完整，不悄悄截断。新格式须带导入器和版本说明。
2. 可恢复备份：一致的 SQLite 数据与完整必要运行状态，包括未完成批次、任务队列、消费进度、分析记录和相关文件。现有 wpack 不是整个 data 的替代品。
导出前记录状态；暂停采集和学习，确认模型任务结束、所管理服务进程确实退出，再做冷备份，或使用经过测试的一致性备份机制。shutdown HTTP 返回成功不代表进程已退出；不只拷运行中的主 SQLite 文件，不删除 WAL/SHM。中途备份完成按原状态恢复；结束试点则保持暂停，明确报告。
交接包包含 SHA256 清单、文件和事件数量、附件数量、时间范围、人员/设备/组织标识、模式版本、基础与派生源码、迁移脚本、候选方法、缺口及恢复说明。机密工作材料加密保存，密码由管理员在本机安全输入并通过独立渠道保管；不打印、不放聊天或包内明文。与必要数据配置区分：不要打包 Codex 登录、GitHub token、系统证书私钥或无关应用凭据。
不上传公司数据库、原件或交接包到 GitHub。原机数据保留到管理员核验接收完整，不能导出后自动清理。

七、开始真实记录前必须完成的验收
先用隔离目录和合成化工案件样本验证：无总控无登记文件也能合法建档；原始文件变化产生可追溯证据；无总控任务仍可按本地计划生成一次总结；重启/暂停/预算控制生效；本地任务回执不会污染联网任务；导出后在隔离接收环境接纳原始身份并重建相同事件、附件、文件版本与总结引用；重复导入不重复入库；跨身份冲突拒绝；完整备份可以检查并恢复未完成状态。
模型模拟测试和真实 Codex 调用分开报告。用本机账号和合成材料验证 gpt-6.1-sol/high 实际可用；未通过时仍可记录，但说明个人自动学习未验收。
合成测试通过后，在员工已登录会话中核验一段实际工作样本及允许目录内一份真实保存版本，证明内容确实入库且可以引用；这不要求员工配合填写操作日志。只有窗口信息就如实报告内容不足。
最后给出简明部署回执：员工/设备编号、源码/运行/数据/备份路径、实际采集范围和缺口、记录运行状态、每日学习时段及额度、最近一次落库总结、暂停/恢复方法、生成交接包命令、测试结果、尚未验证项。明确“尚未连接总控”。开始运行后无变化不反复打扰员工。

请现在从环境核对、必要信息收集、独立派生实现开始，完成上述验收后进入可见工作记录状态。遇到身份冲突、数据完整性问题或不可用能力时保留现状并说明具体阻塞，不伪造成功，不退化成只有截图或空日报的形式工程。
