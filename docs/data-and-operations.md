# 统一数据库与运行边界

每台员工电脑保存 `data/worktrace.sqlite`；总控汇总到自己的同名 SQLite。统一的是事件规范和总控数据库，不是共享一个可写 SQLite 文件。不要把运行中的 SQLite 放 SMB 让多台机器同时写。

原始事件保留 org_id、employee_id、device_id、stream_id/sequence、event_id、UTC 时间/IANA 时区、采集策略摘要、应用、可确定的业务上下文、载荷和附件。员工编号不是姓名，同名员工仍分开。设备登记密钥只允许上传该设备归属的数据。

个人总结 `learning.summary` 的载荷格式 `worktrace.personal/1.0`，有 batch_id/digest、原始证据 ID、补证请求 ID/答复状态和结构化 result。result 包含 summary、coverage、limitations、procedures、open_questions。每项做法含 trigger/inputs、steps[action/decision/check]、outcome、exceptions、corrections、gaps；每个判断注明 observed/inferred/unknown 和来源。没有正式任务/案件编号时为 null，不猜测身份。

固定批次支持中断恢复，保存同样内容幂等，不允许覆盖不同结论。总控分析有自己的派生表 analysis_batches；补证队列 learning_requests 的内容是问题而非命令，每份原始总结最多两组，答复不触发链式追问。字段/引用校验不能证明语义正确，必须核对原文与真实结果。

记录、总结、总控分析、候选技能和业务执行是不同层次。总结中的 observed/inferred/unknown 仍是作者带来源的判断；引用存在不证明判断正确，模型自报和人工反馈声明都不能自动升级为独立验证的事实。按 org_id/employee_id/device_id 和明确时间范围检索，先摘要、后按需读取原文，跨员工比较保留各自来源。

## 独立离线与文件证据

离线节点没有 hub_url、设备同步口令或证书；不会联网重试。公司 UUID 首次生成并持久化，后续同公司离线节点显式沿用；未来总控按原 UUID 接纳来源，原事件编号与摘要保持不变。

`document.version` 使用事件规范1.2；携带文件路径、modified_at、file_sha256、size、extension/mime、previous_event_id、有限解析text、parser/version及gaps。原件按SHA256存于file_versions；同内容不同扩展名共用BLOB，具体类型在事件里。只读稳定保存版本，不能从版本变化推断人工/AI作者或修改理由。包含文件的有界包使用worktrace.bundle/1.1，旧1.0包继续支持。

完整移交使用 `.wthandoff`（worktrace.offline-handoff/1.0）。在线一致SQLite快照保留全部表与WAL已提交内容，不需直接复制运行中的主文件；支持Inspect、同org已接纳身份的Import、只审阅的Restore、原主机暂停恢复的Recover。导出先等待学习/文件解析空闲，暂时暂停；成功后按FinishPilot保留暂停或恢复原状态，失败报告并尝试恢复。详见 [离线手册](offline-collector.md)。

接收时先 Inspect，并在接纳正确公司和设备身份后 Import。导入成功只说明包内证据被接收，不证明员工方法已总结。用 `worktrace_readiness` 按设备查看原始证据与个人总结是否同时存在。只有原始证据时，优先由原分控补做有界个人复盘后重新移交；原分控不可用则在总控暂停自动学习后手动领取 `analysis_next(source="all")`，核对原文并保存明确由总控形成的分析。本版不会据此冒充原员工生成 `learning.summary`，也不会自动生成个人候选。步骤见[总控离线移交说明](../skills/worktrace-hub/references/offline-handoff.md)。

离线电脑没有总控消息通道，不能因收到一次包就向它下发命令、浏览桌面或实时补证。问题通过员工下次移交或另行明确的沟通渠道返回。恢复审阅副本与继续运行原分控不同；跨机器不能克隆同一活动身份，当前没有一键离线转联网功能。

文件解析只提供有限正文。TXT/MD/CSV 支持 UTF-8、UTF-16LE；DOCX 提供部分正文与表内文字；XLSX 提供坐标、原始值和公式缓存；PDF 保存原件但未解析。结构式、公式图片、修订批注及版式均不能据此声称已理解。化工等岗位需要按 `document.version` 的 event_id 用 `file-extract` 导出所存版本到新路径，交给具备对应文件读取能力的交互式 Codex 核对，保留原件和来源；自动 worker 不会自行打开文件或调用这些工具。单原件大小上限默认离线 20MiB、联网 4MiB，放大限制不提高解析能力。

## v0.5.2 学习覆盖与检查点

新个人批次只在最早 1000 条未归组记录的窗口中选样，优先正文、文件版本和结构化业务事件。同 UTC 小时、应用进程、capture_status、完整窗口标题一致的无正文活动可合为一个代表；不同标题不合并。原始事件不删除、不改写，组内成员保留事件引用；未选事件继续待处理。窗口外新记录不参与增量排序；为核验所选证据可另外补入已有前一文件版本、任务起点和有界任务上下文，它们不作为新归组事件消耗。事件很多时仍可能需要多个批次。

`batch.selection` 报告扫描数量、窗口内未选数量和窗口外是否还有记录；这是领取时快照，不是当前积压总量。选样快照保存在本地 meta，兼容旧个人批次及个人总结格式；旧批次缺少快照时返回 null，不补造历史覆盖。`source_coverage` 表明新归组事件、代表证据和补入上下文，采样数量不能作为工时、工作完成率或岗位熟练度。

每日 Markdown 是数据库已保存总结的派生视图，按总结保存日生成，可能处理此前积压；每批列出所引用原始证据的日期范围与局限。手动保存和自动保存均尝试重建，重建失败不撤销已保存总结。可用 admin `personal-digest` 重建，不为重写 Markdown 重跑模型；旧日报不会因今天补做旧证据自动成为完整历史日报。

离线每日学习任务失败或已有已尝试检查点时，必须明确 `worker-retry-local` 或暂停自动学习后手动完成；跨日、重启或恢复网络不自动重付费。总控每批每天最多一次自动尝试，失败或预算耗尽保留检查点，最早下一个本地自然日允许窗口再试。未尝试批次优先于失败重试，未尝试之间仍按到达顺序；总控每天预算共享，并非按员工平均分配，不能保证每位员工当夜都完成。`worker.hub_schedule` 给出近期未完成尝试与下一可重试日期。

实际修改学习配置、离开允许时段或停止运行都会阻止迟到的自动结果落库；重复提交完全相同配置不撤销当前任务。已预留的模型调用次数不退回。联网任务分页轮转，未来任务或暂停任务不再长期挡住后来的消息；未确认和取消回执保留重投，服务收到消息不等于员工或 AI 已答复。

## 备份、复制与导出

- 整体迁移：在对应机器停止服务，复制完整 data 目录（含 SQLite 和未 checkpoint 的 WAL/SHM）并妥善保存凭据。真实换机受 host_binding 约束，先登记新设备，不直接克隆一份活跃分控身份。总控换地址需重新评估证书/登记配置，当前无一键迁移向导。
- 离线汇总：面板按时间/员工导出 `.wpack`，使用至少 12 字符密码。AES-256-GCM 加密；最多 10,000 事件/100MB 原文，超限缩小范围。总结引用的原始证据与相关任务版本会一并带上。重复导入按事件 ID 去重；仅已登记的同公司设备可导入。
- `.wpack` 包含原始事件、个人总结、附件、策略，不包含登录密钥，也不包含总控派生分析、候选 Skill/Loop、节点任务/消息或尚未完成的补证队列。v0.4.0分控完整备份可使用上述一致快照移交包；需要额外调试日志或总控整库时仍按停服全目录备份。原始证据+总结可再次分析。
- 当前无自动保留期限/磁盘清理。总控根据公司要求安排备份和容量巡检，避免无限启用截图导致磁盘增长。SQLite 明文数据库依靠机器/文件权限保护，导出加密不等于本地静态加密。

## 检查实际状态与升级范围

使用 `worktrace_readiness`、技能 `scripts/control.ps1 -Action readiness`，或原部署 Node 的 `src/admin-cli.mjs --command readiness --role collector|hub --dir 原data目录`。角色参数须二选一。报告只读且不调用模型；总控可用 device_id 过滤，limit 默认 20、最大 100、offset 从 0 开始分页。这是按需排查，不应加入每五秒托盘轮询。旧服务没有此接口时先看 status，再按正式升级流程处理，不能把新技能说明当作已运行的新功能。

报告分别指出角色/离线模式、后台任务、数据库/WAL/可用空间、每设备证据与总结缺口及下一步。`latest_evidence_at` 可以来自历史导入，不证明此刻采集健康；“有总结”也不证明所有积压已处理。需要结合 `personal_next` 的覆盖、worker 检查点和实际采集状态。文件扫描失败、学习失败、只记录标题、工作时段外与正常暂停应分别诊断。

| 层次 | 核对位置 | 只更新技能能否更新 |
|---|---|---|
| 实际服务 | 正在运行的 API version、PID、原部署路径 | 不能 |
| 磁盘引擎 | 原运行目录 engine-manifest.json 及文件校验 | 不能 |
| 已安装技能 | 安装来源、受管文件、deployment.json 的 root/role/version | 可以更新技能本体，但不能据此认定运行服务已变 |
| MCP | 注册路径、重新连接后 initialize 的服务版本与工具列表 | 需确认原路径引擎已更新，并重连该 MCP |

本次应更新完整受管引擎、对应角色技能与绑定版本，然后重连本 WorkTrace MCP；不要零散复制几个源码文件形成混合版本。已有部署禁止用 Initialize、Join 或 bootstrap 覆盖初始化。按[本版更新清单与升级步骤](upgrade-v0.5.2.md)，先核验旧源是否有本地修改，暂停并等空闲、停止自己的服务、完整冷备原运行目录与技能，再在原路径替换。保留 data、身份/stream、证据、原件、配置、证书、登记密钥、MCP/登录启动路径、Node 运行时与原暂停状态。冷备哈希用于校验复制；升级后核对原事件 JSON/hash/stream/sequence 与原件摘要，不要求新增索引后 SQLite 整文件字节不变。

同数据目录和同机相同活动身份只允许一个服务；异常停机后先核对已有进程与锁持有者，不删除运行锁绕过冲突。停止服务会等待已开始的后台工作退出；停机未完成前不能直接覆盖数据。升级失败保持暂停，另存失败现场后按已核验冷备回退，不能覆盖失败期间新增的数据。卡顿先用[20 秒只读诊断](collector-performance.md)检查本服务，再按授权做同一应用的暂停/恢复对照；UIA 或 PrintWindow 可能在被观察的应用内消耗资源，WorkTrace 自身 CPU 低不能独自证明不卡。

## 费用控制与软件覆盖

采样、加密、同步、摘要查询不调用模型 API。Codex 在个人复盘和总控分析时消耗各自账户额度；角色模型固定总控 Astra、分控 6.1 Sol；新建默认 xhigh，已有合法 high/xhigh 保留，升级或恢复连接不静默升降强度，见 [夜间循环与成本](nightly-loop.md)。本版没有集成第三方模型调度器。

手动模式默认每批 50 条摘要、每次三批、必要图像最多六张；自动分控每任务最多三批、默认每次最多三图，总控每次一份总结并抽查最多六条原文，按证据 ID 取原文；总结同步后总控优先看总结，避免重复读每人整天屏幕。重复无正文活动按上述完整条件归组；纯元数据程序归纳不调用模型。数据量、截图数量、模型与上下文决定成本，应在试点测量真实用量再预算。

采集、文件版本、个人总结和检索可以用于不同岗位；现有结构化任务 API 仅支持 customer.progress_followup 与 draft.initial_review。其他岗位的业务系统适配、真实动作、权限和结果验收需独立实现，不能通过把岗位名称写入 Skill 就称为自动化完成。

工作日默认 09–18、15 秒采样、闲置 300 秒、正文和截图关闭。关闭 Codex 不影响已启用本地采集；关机/锁屏/休眠、工作时间外、手动暂停均可能无样本。快速操作、未提供可访问控件的软件、编辑框中的未保存文字不能完整重建；只有用过的软件和真实结果才能验证覆盖。语音和业务系统状态仍需明确接口/任务数据补充。允许目录的保存文件版本可按本版支持格式提取，其他文件附件不自动打开。

自动模型输出和必要图片副本保存在 data/analysis-runs，属于工作数据。完整冷备data目录时保留；本版加密移交只含数据库内必要证据、模型总结和状态，不包含这些外部调试日志。当前不自动轮转或删除；管理端应制定保留期限与容量检查。输入超过180000字符时拒绝自动调用，批次保留，暂停自动模式后手动分段核验。
