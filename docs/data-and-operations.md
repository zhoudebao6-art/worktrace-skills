# 统一数据库与运行边界

每台员工电脑保存 `data/worktrace.sqlite`；总控汇总到自己的同名 SQLite。统一的是事件规范和总控数据库，不是共享一个可写 SQLite 文件。不要把运行中的 SQLite 放 SMB 让多台机器同时写。

原始事件保留 org_id、employee_id、device_id、stream_id/sequence、event_id、UTC 时间/IANA 时区、采集策略摘要、应用、可确定的业务上下文、载荷和附件。员工编号不是姓名，同名员工仍分开。设备登记密钥只允许上传该设备归属的数据。

个人总结 `learning.summary` 的载荷格式 `worktrace.personal/1.0`，有 batch_id/digest、原始证据 ID、补证请求 ID/答复状态和结构化 result。result 包含 summary、coverage、limitations、procedures、open_questions。每项做法含 trigger/inputs、steps[action/decision/check]、outcome、exceptions、corrections、gaps；每个判断注明 observed/inferred/unknown 和来源。没有正式任务/案件编号时为 null，不猜测身份。

固定批次支持中断恢复，保存同样内容幂等，不允许覆盖不同结论。总控分析有自己的派生表 analysis_batches；补证队列 learning_requests 的内容是问题而非命令，每份原始总结最多两组，答复不触发链式追问。字段/引用校验不能证明语义正确，必须核对原文与真实结果。

## v0.4.0 独立离线与文件证据

离线节点没有 hub_url、设备同步口令或证书；不会联网重试。公司 UUID 首次生成并持久化，后续同公司离线节点显式沿用；未来总控按原 UUID 接纳来源，原事件编号与摘要保持不变。

`document.version` 使用事件规范1.2；携带文件路径、modified_at、file_sha256、size、extension/mime、previous_event_id、有限解析text、parser/version及gaps。原件按SHA256存于file_versions；同内容不同扩展名共用BLOB，具体类型在事件里。只读稳定保存版本，不能从版本变化推断人工/AI作者或修改理由。包含文件的有界包使用worktrace.bundle/1.1，旧1.0包继续支持。

完整移交使用 `.wthandoff`（worktrace.offline-handoff/1.0）。在线一致SQLite快照保留全部表与WAL已提交内容，不需直接复制运行中的主文件；支持Inspect、同org已接纳身份的Import、只审阅的Restore、原主机暂停恢复的Recover。导出先等待学习/文件解析空闲，暂时暂停；成功后按FinishPilot保留暂停或恢复原状态，失败报告并尝试恢复。详见 [离线手册](offline-collector.md)。

## 备份、复制与导出

- 整体迁移：在对应机器停止服务，复制完整 data 目录（含 SQLite 和未 checkpoint 的 WAL/SHM）并妥善保存凭据。真实换机受 host_binding 约束，先登记新设备，不直接克隆一份活跃分控身份。总控换地址需重新评估证书/登记配置，当前无一键迁移向导。
- 离线汇总：面板按时间/员工导出 `.wpack`，使用至少 12 字符密码。AES-256-GCM 加密；最多 10,000 事件/100MB 原文，超限缩小范围。总结引用的原始证据与相关任务版本会一并带上。重复导入按事件 ID 去重；仅已登记的同公司设备可导入。
- `.wpack` 包含原始事件、个人总结、附件、策略，不包含登录密钥，也不包含总控派生分析、候选 Skill/Loop、节点任务/消息或尚未完成的补证队列。v0.4.0分控完整备份可使用上述一致快照移交包；需要额外调试日志或总控整库时仍按停服全目录备份。原始证据+总结可再次分析。
- 当前无自动保留期限/磁盘清理。总控根据公司要求安排备份和容量巡检，避免无限启用截图导致磁盘增长。SQLite 明文数据库依靠机器/文件权限保护，导出加密不等于本地静态加密。

## 费用控制与软件覆盖

采样、加密、同步、摘要查询不调用模型 API。Codex 在个人复盘和总控分析时消耗各自账户额度；自动执行器固定总控 Astra/xhigh、分控 6.1 Sol/xhigh，见 [夜间循环与成本](nightly-loop.md)。本版没有集成第三方模型调度器。

手动模式默认每批 50 条摘要、每次三批、必要图像最多六张；自动分控每任务最多三批、默认每次最多三图，总控每次一份总结并抽查最多六条原文，按证据 ID 取原文；总结同步后总控优先看总结，避免重复读每人整天屏幕。重复无正文活动按小时/应用聚合；纯元数据程序归纳不调用模型。数据量、截图数量、模型与上下文决定成本，应在试点测量真实用量再预算。

工作日默认 09–18、15 秒采样、闲置 300 秒、正文和截图关闭。关闭 Codex 不影响已启用本地采集；关机/锁屏/休眠、工作时间外、手动暂停均可能无样本。快速操作、未提供可访问控件的软件、编辑框中的未保存文字不能完整重建；只有用过的软件和真实结果才能验证覆盖。语音和业务系统状态仍需明确接口/任务数据补充。允许目录的保存文件版本可按本版支持格式提取，其他文件附件不自动打开。

自动模型输出和必要图片副本保存在 data/analysis-runs，属于工作数据。完整冷备data目录时保留；本版加密移交只含数据库内必要证据、模型总结和状态，不包含这些外部调试日志。当前不自动轮转或删除；管理端应制定保留期限与容量检查。输入超过180000字符时拒绝自动调用，批次保留，暂停自动模式后手动分段核验。
