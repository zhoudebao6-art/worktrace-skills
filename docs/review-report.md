# WorkTrace v0.2 结构审查、优化及验证报告

日期：2026-10-13。用途：在公司已告知的固定员工电脑上积累工作证据、学习个人方法，并由独立总控归纳岗位技能。开发电脑不是公司总控。

## 结论

当前适合采用“被动采集服务 + 分控个人学习 + 总控任务队列 + 总控知识整理”的结构。只部署监控软件缺少业务语义与结果；只写 Skill 又缺少稳定的采集、消息、重试和进度保存。这次把两部分分开实现，并提供了可运行闭环。

模型按用户要求固定：**总控 gpt-6-astra / high，分控 gpt-6.1-sol / high**。实际调用参数由执行器传入，不依赖模型自行记住。采样、同步、排队和纯活动归纳不调用模型。读取本机模型目录并完成两种模型的真实合成案例调用，均支持该设置。

这套方案可用于先一总控、两名客服试点，尚不能宣称已替代员工。最大的剩余问题是证据覆盖：UIA/截图只能记录可见片段，判断理由、案件状态与实际结果仍需业务系统或任务版本提供。下一阶段优先接案件系统的客户/案件编号、状态与产出，价值通常高于继续加密截图频率。

## 实际结构

```mermaid
flowchart LR
  A[工作软件与任务版本] --> B[分控本地证据库]
  B --> C[Sol high 个人方法学习]
  C --> B
  B -->|HTTPS 事件与回执| D[总控统一库]
  D -->|任务和补证 下次同步领取| B
  D --> E[Astra high 总控分析]
  E --> F[有来源的候选 Skill 与 Loop]
  F --> G[总控跨员工比较与留出案例评估]
  G -->|缺证| D
  G --> H[另行验收具体业务执行]
```

每台本地 SQLite 独立写入，总控服务独占汇总库写入入口；不共享写一个网络盘数据库。统一身份、事件 ID、设备序列、UTC 时间、采集策略、任务和版本引用，保证可追溯。断线先本地保存，恢复后按确认序列补传。

分控主动 HTTPS 同步同时上传事件/回执/AI 回复和领取任务，默认 30 秒。不要求总控入站访问每台员工电脑，也不通过远程任意 shell 控制它。节点必须事先安装接入并启用对应执行器。

## 发现并修复的问题

| 问题 | 优化结果 |
|---|---|
| 把 Skill 当常驻服务或无限模型循环 | 定时、持久化队列、状态与限额交给普通服务；模型只处理具体证据批次 |
| 打开应用被误认为“学会工作” | 总结明确操作、判断、检查、结果与未知；只有元数据时程序归纳并保留缺口 |
| 高频无正文采样反复占上下文 | 同小时/应用/状态聚合代表样本并保留数量；200 条重复元数据与两条不同正文形成三条代表项，原始记录仍保留 |
| 同 UIA 文字下截图变化被去重 | 去重加入图像哈希，图像变化独立保存 |
| 大截图数量少也超过同步请求上限 | 发送前按字节拆包，短包后仍继续补传；八份 2MB 传输夹具经真实 HTTPS 全部到达 |
| 新人工版本缺少前文或查询扫描全库 | 补任务起点、直接父版本和最近版本；任务索引与按关联 ID 导出避免读取全库 JSON |
| 时区固定、中文窗口标题读取问题 | 工作事件沿用实际策略时区；Windows 标题调用使用 Unicode |
| 无效策略意外暂停采集 | 先验证设置，再改变采集状态 |
| 重复下发任务、重启后重复付费 | 稳定幂等键；running 重启转 interrupted，保留检查点，不盲目重跑 |
| 取消回执不收敛、未来任务堵住队头 | 独立确认取消送达；按可执行时间选任务，105 个未来任务不阻塞当前任务 |
| 自动与手动复盘争用同一批次 | 手动领取/保存前要求自动学习暂停；正在运行的模型返回后再次核对暂停与取消 |
| 普通消息被误报员工已读 | 服务收件、执行回执、分控 AI 文字回复分开记录，employee_read=false |
| 总控只读个人总结，缺原文核验 | 自动分析附带最多六条有界原始证据抽查，未附内容仍标未核验 |
| 候选技能无来源、直接变正式规则 | 每项个人方法生成 draft 候选，保留原始 ID、总结、分析批次、Loop 上限与待评估项；不自动安装 |
| 角色猜测、源码不可移植、运行时过大 | 明确角色绑定；可单独复制总控 Skill，按 SHA256 部署源码和官方固定运行时；Git 不含 Node 二进制、数据或凭据 |

## 夜间循环与学习质量

总控按工作日创建每设备任务 → 分控领取 → 在本机时段/预算内分析新增证据 → 保存结构化个人总结 → 回传 → 总控核验并生成候选 → 总控进一步跨员工比较、补证和留出评估。没有新增材料、达到预算、缺输入或发生故障即退出。

自动部分已实现任务、消息、回执、个人总结、总控逐份分析与个人候选草稿。**跨员工通用规则的综合、主动提出哪些补证问题、完善通用 Loop 和独立业务验收，由总控 Skill 继续完成；当前后台不会自动批准或发布候选。** 这一区分避免把自动生成的初稿当作成熟的岗位智能体。

学习验收应逐层进行：有证据 → 能解释步骤/条件 → 别人能复现草稿 → 留出案例能处理正常与异常 → 接口执行有真实回执。仅结构校验、模型自评或一天采样都不足以证明最后一层。客服先选案件进度回复草稿、材料缺项跟进；收费与案件状态必须来源明确。

真实模型样本用量：Sol 输入 12,213 / 输出 1,175 token；Astra 输入 12,595 / 输出 916 token。此数据包括 Codex 自身上下文，属于一次合成样本，不能外推每天费用；服务也不是绕过额度的渠道。后续增加有界原文抽查通过程序回归，但尚未建立大规模业务质量指标。执行器禁用用户 MCP、桌面、Shell、插件与网络搜索工具，指定角色模型不可用时不换模型重试。

部署测试显式 SkipMcp，避免改变开发电脑全局配置；MCP 协议单独运行验证。测试服务已正常结束，原微信任务保持暂停。测试 TEMP/TMP 和 Node/Python 缓存放在 D:\codex+；C 盘临时目录未发现以本项目命名的新缓存，未清理来源不明的其他应用文件。

## 尚未验证与运行限制

- 尚未到目标 LAN 的真实多电脑验收：共享权限、防火墙、账号可用额度、锁屏/休眠/注销行为与软件正文覆盖须现场确认。
- 未验证真实客户工作的理解正确率、图像语义质量、长期容量与替代人工比例。当前不解析语音、聊天附件文件或保证识别所有软件动作。
- 总控自动逐份分析有日限额；首批一两人合适，员工增加后需监测积压。只有单节点串行与各节点每日预算，尚无全公司模型并发闸门或精确金额硬限额。
- 初始生成的候选由总控完善；没有自动业务执行适配器、案件系统写入或微信发送功能。下班任务读取已保存证据，不会解锁桌面、翻阅新的微信历史。
- 无自动保留期限、轮转与清理；SQLite、模型结果及图片副本需按公司方案备份。离线 wpack 带原始事件/总结/附件/策略，完整候选、分析、任务与消息需停止服务后备份整个 data。
- 首版升级保留旧目录和数据，不自动覆盖不同源码；更换设备、总控 IP 或证书须按实际环境重新登记/配置。

## 交给真实总控的总步骤

1. 从独立仓库取源码，在指定总控安装 worktrace-hub Skill，保留开发电脑与生产数据隔离。
2. 提供真实公司名、总控 IP、独立部署目录，bootstrap 后初始化并核对 MCP。
3. 按固定员工编号准备只读源码共享和每人私有接入目录；由现有公司执行通道或员工已登录桌面运行一次 Join。
4. 用一总控两分控核验心跳、实际应用内容、暂停与断线补传；心跳不等于内容可读。
5. 分别启用 Sol/high、Astra/high 夜间执行器，总控开启 AutoDispatch；验证消息来回、总结、候选、取消、重启和预算。
6. 总控用实际脱敏案例完善个人方法与通用 Loop；缺案件事实时接系统接口，保持客户/案件编号和真实结果证据一致。
7. 留出案例通过后再逐项接入业务执行器，逐步提高自动化范围。
