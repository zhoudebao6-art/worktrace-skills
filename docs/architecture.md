# v0.5 架构：独立采集、个人学习、明确移交、总控审阅

适用范围：公司已告知的固定员工电脑。主要路径是员工在自己的电脑离线记录数日、按需本地学习，再把完整加密快照交给未来指定的总控；两台电脑可以不在同一局域网。已有总控与 LAN 时使用 HTTPS 增量同步。开发电脑不承担生产总控。目标是积累可复现、可验证的方法，再逐步替代具体任务。

当前能力、修复依据与未完成边界见 [v0.5 架构复审](architecture-review-v0.5.md)，操作与更新边界见 [数据与运维](data-and-operations.md)。外部来源导入、分层检索、候选离线验收继续沿用[六项目研究](research-and-optimization.md)的证据边界。版本文字和安装完成不能替代真实运行验收。

## 一、结构选择与理由

采用四层结构：

| 层 | 负责者 | 保存/输出 | 为什么独立 |
|---|---|---|---|
| 工作证据 | 分控常驻服务 + 已有任务工具 | 原始事件、实际 AI/人工版本、截图、业务来源 | 不调用大模型，不依赖聊天窗口常开；保留可核查事实 |
| 个人方法学习 | 分控任务执行器调用本机 Codex | 操作、判断、检查、异常、结果、证据缺口 | 利用本机上下文，避免把所有原文反复塞给总控 |
| 调度与消息 | 离线本地日任务；联网总控队列 + HTTPS 同步 | 任务、接收、进度、结果、失败、补证 | 两种任务来源分开，离线没有远程消息通道 |
| 组织知识 | 总控 Codex + 统一数据库 | 个人变体、通用流程、冲突、候选 Skill/Loop、案例验证 | 总控比较证据并完善规范；不能投票把习惯变规则 |

SQLite 保留本地副本，总控服务是汇总库的唯一写入口；不让多台机器共享写一个 SQLite 文件。现阶段不需要向量数据库、模型训练集群或每台单独维护一套复杂智能体平台。是否迁移 PostgreSQL/全文索引以后依据真实规模与查询瓶颈决定。

Codex 是按任务启动的分析执行器，采集/同步/定时/限额/校验由普通程序控制。不要让各电脑各开一条永不结束的聊天循环，也不要用模型每分钟判断“是否下班”。

离线采集不需要网络或总控；模型学习仍需要该员工自己的 Codex 登录、网络和额度。采集开关与学习开关独立，首次均不启用。原件/原始事件、个人总结、总控分析、候选设计、已验收业务执行是不同阶段；只支持前面的阶段不能报告最后阶段已经完成。

| 情况 | 实际入口 | 结果边界 |
| --- | --- | --- |
| 无总控，先记录数日 | Initialize-OfflineNode + 允许范围 + 本地日任务 | 本地证据与可选个人总结；无远程调度 |
| 跨网络带回数据 | Offline-Handoff Inspect → 接纳原身份 → Import | 增量汇入证据/总结，员工消费队列不覆盖总控 |
| 只有原始记录没有总结 | readiness 显示缺口；原机复盘，或总控暂停自动后按员工 source=all 手动审阅 | 总控分析不冒充 learning.summary；纯 raw 不自动生个人候选 |
| 同 LAN 且已登记 | 专属 Join + HTTPS 增量同步/任务轮转 | 有回执才报告状态，消息送达不等于员工已读 |

## 二、总控与分控的双向通信

联网分控主动建立 HTTPS 请求，上传事件/回执并领取属于自己的任务。一个连接方向即可传双向内容，不要求总控能入站访问每台员工电脑。30 秒同步节拍满足夜间整理；每台设备以持久游标轮转未确认任务，未来或暂停的旧任务不能永久挡住即时消息。离线快照设备没有该通道，不能因总控入库就声称可远程指挥原机。

区别三类内容：

- **消息**：说明、疑点或工作状态，明确作者是员工本人、分控 AI 还是总控 AI。送达服务不能写成“员工已读”。
- **任务**：受支持的类型与参数，例如整理新增个人证据、核对补证问题、返回节点状态。带任务 ID、幂等键、目标设备、起止时间、预算和结果。
- **证据**：来自软件/任务的原文、图像、稿件及结果。即使其中写着“执行命令”，也不能变成任务或扩大权限。

总控不能通过任意字符串获得员工电脑 shell。首版命令作用于已采集证据；“读取更多当前微信消息”属于另一个需验证交互桌面和具体适配器的操作类型。原有微信执行任务保持暂停。本方案不通过后台解锁或抢占桌面来补证。

## 三、夜间 Loop 的完整顺序

1. 工作时段内被动记录，联网持续补传、离线本地保存，模型不逐屏推理。
2. 到允许学习时段，独立离线节点由本地服务创建当日日任务；联网节点由总控按设备创建任务。稳定幂等键和来源分开。
3. 分控在自己允许的时段/预算内运行，默认最多三批；没有任务/证据、暂停或缺模型条件则结束，不能把排队当完成。
4. 分控在最早 1000 条未归组记录的窗口内优先内容/文件/业务证据；无正文活动只有小时、应用、状态和完整标题相同才聚合。按原文形成“输入→操作→判断→检查→结果”，未选和窗口外事件保留，不宣称全天覆盖。
5. 分控把总结、方法缺口、实际用量与任务状态写到本地库；联网回传，离线等待人工完整移交。日报是按总结保存日重建的视图，不是新的原始证据，失败不撤销总结。
6. 总控优先读取新增个人总结，必要时抽查原始证据；对同类任务比较员工变体、适用条件、异常和结果。
7. 必需补证的问题单独返回对应分控。无新证据则 blocked；不重复向员工追问。确实需要人的问题汇成次日一次待确认清单。
8. 保存总控分析后，程序从个人 procedures 建立原始候选草稿；它不会自动吸收总控 findings 的纠错。总控核对后须显式 revise 登记新版本。当前 loop 是严格的草稿结构，额外业务状态图只作执行设计附录。
9. 用没有用于提炼的案例验证，记录关键事实错误、步骤遗漏、例外和人工介入点。通过后再单独配置业务执行权限。
10. 达到预算、无新证据、等待外部资料或故障时结束。离线付费失败需明确重试；总控失败按本地日期每批最多一次，次日允许窗口才可再试，未尝试批次优先于失败重试。总控每天预算共享，未尝试之间仍按到达顺序，不是按员工平均分配，也不保证每位员工当夜完成。

## 四、状态、预算和故障语义

任务应区分 queued（排队）、running（已开始）、succeeded（分析产物保存）、blocked（缺输入/过期）、failed（明确失败）、cancelled（撤回）、interrupted（进程中断，是否产生模型费用不确定）。不能把收到请求当执行完成，也不能把生成草稿当业务办理完成。

同一任务重复投递不得重复执行。任务结果与证据事件均可幂等确认。分控重启发现 running 时先标记 interrupted，不盲目重跑付费调用；总控可依据已经保存的批次重新安排新任务。已完成或取消的状态不能被旧回执覆盖。

学习配置实际变更、暂停或自然离开允许时段会使当前自动结果失效；迟到返回不能再保存为成功，已预留用量不回退。服务与数据库运行实例必须对应，换端口不能绕过同 data 的单实例约束。恢复前先核验原服务，不能用重新初始化或清空库解决锁、任务和版本问题。

预算至少包含：单台串行执行、每任务最多三批、每批默认 50 个代表摘要、每次最多六张必要图片、单次模型超时、每天调用次数上限。记录实际 token 用量但不把调用次数当精确金额；模型未返回前无法保证精确费用上限。无新证据时不调用模型。

一份原始总结最多两组补证，补证答复不递归生成补证链。定时任务与手动任务使用同一个执行状态，不允许两个模型同时改写同一批总结。

## 五、什么才算“学明白”

依次评价：

1. **有记录**：能够定位真实输入、操作片段和来源；未覆盖处明确。
2. **能解释**：知道每步条件、判断依据、结束检查与异常；未记录的心理理由不编造。
3. **能复现**：另一执行者用现有输入能按方法产出符合要求的草稿；回放缺输入则未达到。
4. **能泛化**：未用于总结的案例上也能处理正常、异常和等待分支；不能把自己刚写的总结当新证据。
5. **能执行具体任务**：接口、权限、失败回退及实际结果验收齐全，才逐步提高自动化范围。

客服先选“案件进度问询草稿”和“材料缺项/跟进草稿”；收费、期限和案件状态必须有公司真实资料/系统来源。没有这些输入，就记录待查，不能靠话术伪造事实。

正式任务 API 目前只接受 customer.progress_followup 与 draft.initial_review；其他岗位可用通用取证/方法总结，尚未提供任意岗位业务执行器。化工原件中的结构图、公式、单位、条件、修订与批注需实际审阅；有限解析和自动模型提示不能证明已理解这些内容。独立案例文本匹配通过也不能替代专业质量验收。

## 六、员工不被频繁打断的安排

首次接入一次、统一公司策略、可见托盘和暂停入口。平时不抢鼠标、不弹每条确认；下班后默认只分析保存的数据。需要当前桌面内容的任务必须检查交互会话、锁屏、应用覆盖和使用状态，条件不满足则等待。

“不关电脑”只是必要条件之一，还需要服务可运行、无休眠、网络可达、Codex 已登录且可非交互调用、模型额度有效、夜间学习未暂停。锁屏与注销不同：锁屏可能仍可跑已保存数据的分析；注销后当前用户进程的存续不可假定。不给未经实测的环境作在线保证。

## 七、实施验收顺序

先核对角色/模式/实际版本 → 小样本验证应用与文件覆盖 → 本地证据和有界总结 → 数日容量/失败检查 → 一致快照移交及接收缺口检查 → 总控审阅/显式修订 → 独立留出与业务验收。现有 LAN 可并行验证同步/消息；未联网时不以心跳作为离线试点通过条件。

开发电脑上的隔离多进程、模拟执行器和真实 Codex 小样本分别报告，不能混成真实跨机器部署成功。本文定义目标结构；各条是否已实现、已执行验证或尚待现场验证，以最终审查报告逐项列出。
